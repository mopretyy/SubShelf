# Публикация SubShelf

Как выпустить приложение в Google Play, App Store и как продавать Pro напрямую через APK. Всё собирается на GitHub Actions: Mac и Android Studio не нужны.

## Каналы

| Канал       | Файл сборки                                  | Как платят за Pro                      | Какие телефоны                                                                                                      |
| ----------- | -------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Google Play | `SubShelf-1.0.N-play.aab` из GitHub Releases | Google Play Billing (через RevenueCat) | Все Android с сервисами Google: Samsung, Xiaomi / Redmi / POCO, Pixel, OnePlus, Realme, Oppo, Vivo, Motorola, Honor |
| App Store   | Actions → «iOS release (TestFlight)»         | покупки Apple (через RevenueCat)       | iPhone, iPad (iOS 15+)                                                                                              |
| APK         | `SubShelf-1.0.N.apk` из GitHub Releases      | ключ активации, оплата любым способом  | Любой Android 7+, в том числе Huawei без сервисов Google                                                            |
| Веб-демо    | `npm run dev`                                | демо-покупка, деньги не списываются    | Браузер, только для просмотра                                                                                       |

- **Samsung.** На всех Samsung есть Google Play, отдельно публиковаться в Galaxy Store не нужно.
- **Huawei.** На телефонах Huawei, выпущенных с 2019 года, нет Google Play. Им подходит APK (или AppGallery, см. раздел 6). Телефоны на **HarmonyOS NEXT** (HarmonyOS 5, в основном продаются в Китае) не запускают Android-приложения совсем, им нужна отдельная версия.
- Какой канал собран, задаёт переменная `VITE_STORE`: `play`, `appstore`, `direct` (APK), `web`. GitHub Actions выставляет её сам.

## Free и Pro

| Free                                        | Pro                                                    |
| ------------------------------------------- | ------------------------------------------------------ |
| До 5 активных подписок (пробные + активные) | Безлимит подписок                                      |
| Напоминания, история, сумма в месяц         | Обзор: прогноз на 12 месяцев, категории, самые дорогие |
| Резервная копия JSON                        | Календарь списаний, экспорт в CSV                      |

Цены (рекомендованные): **$1.99 в месяц**, **$9.99 в год** с бесплатной неделей, **$24.99 навсегда**. Цены задаются в консолях магазинов, приложение показывает их из магазина в валюте пользователя.

Кто пользовался SubShelf до этого обновления (на телефоне уже были данные), получает Pro бесплатно как ранний пользователь.

## 1. RevenueCat

RevenueCat проверяет покупки в Google Play и App Store и сообщает приложению, есть ли у пользователя Pro. Бесплатно до $2 500 выручки в месяц (проверьте актуальные условия на revenuecat.com/pricing).

1. Зарегистрируйтесь на [app.revenuecat.com](https://app.revenuecat.com), создайте проект **SubShelf**.
2. **Apps** → добавьте два приложения:
   - App Store: bundle ID `io.github.dimon4w.subshelf`;
   - Google Play: package name `io.github.dimon4w.subshelf`.
3. **Entitlements** → создайте `pro`.
4. Создайте товары в магазинах (разделы 2 и 3), затем **Products** → импортируйте их и привяжите все к `pro`:

   | Магазин     | Товар                                                                  |
   | ----------- | ---------------------------------------------------------------------- |
   | App Store   | `subshelf_pro_monthly`, `subshelf_pro_yearly`, `subshelf_pro_lifetime` |
   | Google Play | `subshelf_pro:monthly`, `subshelf_pro:yearly`, `subshelf_pro_lifetime` |

5. **Offerings** → создайте `default` и сделайте его текущим (Current). Добавьте три пакета и в каждом выберите товар App Store и товар Google Play:
   - `$rc_monthly` (Monthly) → месячная подписка;
   - `$rc_annual` (Annual) → годовая;
   - `$rc_lifetime` (Lifetime) → навсегда.
6. **API keys** → скопируйте публичные SDK-ключи: `appl_…` в переменную GitHub `RC_IOS_KEY`, `goog_…` в `RC_ANDROID_KEY` (раздел 4). Эти ключи не секретные.

## 2. Google Play

1. **Аккаунт разработчика.** [play.google.com/console](https://play.google.com/console), разовый взнос $25. Новые личные аккаунты перед выходом в продакшен обязаны провести закрытое тестирование: минимум 12 тестировщиков в течение 14 дней. Начните его как можно раньше.
2. **Платёжный профиль.** Console → Настройки → Платёжный профиль. Без него нельзя продавать. Убедитесь, что ваша страна есть в списке стран, где Google разрешает продавать.
3. **Создать приложение.** Название `SubShelf`, язык по умолчанию русский, тип «Приложение», «Бесплатное» (Pro продаётся внутри).
4. **Первая загрузка.** Тестирование → Внутреннее тестирование → Создать выпуск → загрузите `SubShelf-1.0.N-play.aab` из [GitHub Releases](https://github.com/mopretyy/SubShelf/releases/latest).
   - Google предложит **Play App Signing**. Если согласиться с ключом Google, версия из Play и APK с GitHub будут подписаны разными ключами: одна не встанет поверх другой. Пользователю, который переходит с APK на Play, нужно сделать резервную копию, удалить APK, поставить из Play и восстановить копию.
5. **Товары.** Монетизация → Товары. Создать их можно только после загрузки сборки (шаг 4), в ней уже есть разрешение на платежи.
   - Подписки → `subshelf_pro`, базовые планы `monthly` (продлевается каждый месяц, $1.99) и `yearly` (каждый год, $9.99). Для `yearly` добавьте предложение «Бесплатный пробный период 7 дней» для новых клиентов. Активируйте.
   - Внутренние товары → `subshelf_pro_lifetime`, $24.99. Активируйте.
6. **Связь с RevenueCat.** В Google Cloud создайте сервисный аккаунт и JSON-ключ, включите Google Play Android Developer API. В Play Console → Пользователи и разрешения пригласите email сервисного аккаунта с правами «Просмотр информации о приложении», «Просмотр финансовых данных», «Управление заказами и подписками». Загрузите JSON в RevenueCat (настройки Google Play приложения). Пошагово: [docs.revenuecat.com → Google Play service credentials](https://www.revenuecat.com/docs/service-credentials/creating-play-service-credentials). Ключ начинает работать в течение 36 часов.
7. **Тестовые покупки.** Настройки → Тестирование лицензий → добавьте свой Gmail. Покупки с этого аккаунта бесплатные, подписка продлевается каждые несколько минут.
8. **Содержание приложения** (Policy → App content):
   - Политика конфиденциальности: `https://github.com/mopretyy/SubShelf/blob/main/docs/PRIVACY.md`;
   - Реклама: нет;
   - Доступ к приложению: всё доступно без входа;
   - Финансовые функции: «Приложение не предоставляет финансовых услуг»;
   - Возрастной рейтинг, целевая аудитория и Безопасность данных: ответы в [STORE_LISTING.md](STORE_LISTING.md).
9. **Страница в магазине.** Тексты из [STORE_LISTING.md](STORE_LISTING.md), значок 512×512, обложка 1024×500, 2–8 скриншотов телефона.
10. **Продакшен.** После закрытого тестирования: Рабочая версия → Создать выпуск → тот же AAB или новый.

Каждый пуш в `main` собирает новый AAB с бо́льшим номером версии, его и загружайте в следующие выпуски.

## 3. App Store

1. **Apple Developer Program.** [developer.apple.com/programs](https://developer.apple.com/programs), $99 в год.
2. **Договор о платных приложениях.** App Store Connect → Бизнес → подпишите Paid Apps Agreement, заполните банк и налоги. Без него покупки не работают даже в тестах.
3. **App ID.** developer.apple.com → Certificates, IDs & Profiles → Identifiers → **+** → App ID `io.github.dimon4w.subshelf`. In-App Purchase включён по умолчанию.
4. **Приложение.** App Store Connect → Приложения → **+** → iOS, имя `SubShelf: Subscription Tracker` (или `SubShelf`, если свободно), основной язык русский, bundle ID выше, SKU `subshelf`.
5. **Подписки.** Монетизация → Подписки → группа «SubShelf Pro»:
   - `subshelf_pro_monthly`: 1 месяц, $1.99;
   - `subshelf_pro_yearly`: 1 год, $9.99, вводное предложение «Бесплатно, 1 неделя».

   Заполните название и описание на русском и английском и приложите скриншот экрана Pro (нужен для проверки).

   Встроенные покупки → Не расходуемая → `subshelf_pro_lifetime`, $24.99.

6. **Связь с RevenueCat.** Пользователи и доступ → Интеграции → In-App Purchase → создайте ключ `.p8` и загрузите его в RevenueCat (настройки App Store приложения) вместе с Issuer ID.
7. **API-ключ для сборки.** Пользователи и доступ → Интеграции → App Store Connect API → Ключи команды → **+**, роль **Admin** (нужна, чтобы сборка сама создавала сертификаты). Скачайте `.p8` (его дают один раз), запишите Key ID и Issuer ID. Team ID: developer.apple.com → Membership. Внесите всё в GitHub (раздел 4).
8. **Сборка.** GitHub → Actions → **iOS release (TestFlight)** → Run workflow. Через 10–30 минут после окончания сборка появится в TestFlight. Вопрос о шифровании уже закрыт в `Info.plist`.
9. **Тестовые покупки.** Поставьте сборку через TestFlight: покупки в ней бесплатные. Или создайте тестировщика в Пользователи и доступ → Sandbox и войдите им в Настройки → App Store → Sandbox-аккаунт.
10. **Отправка на проверку.** На странице версии:
    - скриншоты iPhone 6.9″ (1320×2868) или 6.7″ (1290×2796). Приложение поддерживает iPad, поэтому нужны и скриншоты iPad 13″ (2064×2752). Если iPad не нужен, перед первой отправкой поставьте `TARGETED_DEVICE_FAMILY = 1` в `ios/App/App.xcodeproj`;
    - добавьте все три покупки к версии: первую подписку Apple проверяет только вместе с версией приложения;
    - ссылки: политика конфиденциальности и условия использования (`docs/PRIVACY.md`, `docs/TERMS.md`);
    - заметки для проверяющих: в [STORE_LISTING.md](STORE_LISTING.md).

## 4. GitHub: переменные и секреты

Репозиторий → Settings → Secrets and variables → Actions.

| Имя                         | Тип      | Что внутри                                    | Где взять                         |
| --------------------------- | -------- | --------------------------------------------- | --------------------------------- |
| `ANDROID_KEYSTORE_B64`      | Secret   | ключ подписи Android (PKCS#12) в base64       | уже настроен                      |
| `ANDROID_KEYSTORE_PASSWORD` | Secret   | пароль ключа (алиас `subshelf`)               | уже настроен                      |
| `RC_ANDROID_KEY`            | Variable | публичный SDK-ключ RevenueCat `goog_…`        | RevenueCat → API keys             |
| `RC_IOS_KEY`                | Variable | публичный SDK-ключ RevenueCat `appl_…`        | RevenueCat → API keys             |
| `LICENSE_PUBKEY`            | Variable | публичный ключ для ключей активации (hex)     | `node scripts/license.mjs keygen` |
| `BUY_URL`                   | Variable | где купить ключ: Telegram, Boosty, сайт       | ваша ссылка                       |
| `SUPPORT_EMAIL`             | Variable | почта поддержки, видна в приложении           | ваша почта                        |
| `APPLE_TEAM_ID`             | Variable | Team ID из 10 символов                        | developer.apple.com → Membership  |
| `APPSTORE_API_KEY_ID`       | Secret   | Key ID API-ключа App Store Connect            | раздел 3, шаг 7                   |
| `APPSTORE_API_ISSUER_ID`    | Secret   | Issuer ID                                     | раздел 3, шаг 7                   |
| `APPSTORE_API_KEY_P8`       | Secret   | содержимое файла `.p8` целиком (или в base64) | раздел 3, шаг 7                   |

Сборки:

- **CI** (`.github/workflows/ci.yml`): каждая ветка, кроме `main`, и каждый pull request. Проверки, отладочная сборка Android и сборка iOS для симулятора.
- **Android release** (`android.yml`): каждый пуш в `main`. Подписанные APK и AAB, релиз `v1.0.N` на GitHub.
- **iOS release** (`ios.yml`): вручную, загрузка в TestFlight.

## 5. APK и ключи активации

В APK с GitHub Pro включается ключом: вы продаёте ключ любым способом (перевод, Telegram, Boosty), покупатель вводит его в приложении. Ключ проверяется на телефоне без интернета и сервера.

Ввод ключа есть **только в APK**. В сборках для Google Play и App Store его нет: правила этих магазинов запрещают открывать платные функции мимо их оплаты.

1. **Один раз** на своём компьютере (нужен Node.js), в папке проекта: `node scripts/license.mjs keygen`.
   - Приватный ключ сохранится в файл `subshelf-license.key` в текущей папке, а в консоли появится публичный ключ (64 символа). Файлы `*.key` уже в `.gitignore`, но надёжнее перенести файл из папки проекта, например в менеджер паролей или на флешку, и указывать путь через `--key`.
   - Не отправляйте приватный ключ никому: кто его знает, может выпускать ключи сам.
   - Если приватный ключ потерян, выданные ключи продолжат работать, но новые выпустить не получится. Придётся сделать новую пару и новый APK, и тогда старые ключи в новой версии перестанут работать.
   - Публичный ключ можно в любой момент вывести снова: `node scripts/license.mjs pubkey --key путь/к/subshelf-license.key`.
2. В GitHub задайте `LICENSE_PUBKEY` (публичный ключ) и `BUY_URL` (где купить). Сделайте пуш в `main`: новый APK будет принимать ключи.
3. **Продажа.** Человек платит, вы выполняете:
   - навсегда: `node scripts/license.mjs issue --note "Имя покупателя"`;
   - на год: добавьте `--months 12` (или точную дату: `--until 2027-12-31`);
   - если ключ лежит не в текущей папке: добавьте `--key путь/к/subshelf-license.key`.

   Команда печатает ключ вида `SUBSHELF-…`, отправьте его покупателю. Он вводит ключ в приложении: Профиль → Pro или Настройки → «Ввести ключ». Каждый выданный ключ записывается в `subshelf-licenses.csv` рядом с приватным ключом (дата, номер, срок, заметка). Проверить ключ: `node scripts/license.mjs check SUBSHELF-…`.

4. Ключ не привязан к телефону: им можно поделиться. Для недорогого Pro это нормально. Если нужна защита строже, продавайте через Google Play.

## 6. Другие магазины

- **Huawei AppGallery.** Оплаты Huawei (HMS In-App Purchases) в приложении нет. APK можно загрузить в AppGallery, но перед этим проверьте правила AppGallery об оплате цифровых товаров. Если продавать Pro ключами там нельзя, выложите сборку без продажи Pro или подключите HMS IAP (отдельная доработка: нативный плагин и новый способ оплаты в коде).
- **Samsung Galaxy Store.** Samsung In-App Purchase не подключён. Публиковаться там не обязательно: на всех Samsung есть Google Play.
- **RuStore.** Платёжный SDK RuStore не подключён. APK загрузить можно, но сначала проверьте правила RuStore о продаже цифровых товаров и ключах активации.
- **Xiaomi GetApps и другие.** То же, что для RuStore: APK подходит, платёжные SDK этих магазинов не подключены.
